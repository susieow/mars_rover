# 火星车台阶实验

本项目为火星车爬楼数据集寻找可用经验。实验一保留 **20 cm、45°、15级** 的探索结果；实验二在甲方URDF明确约束内固定 **20 cm、15级**，只改变倾角，以六轮登上平台并正常停稳为终点，暂不测试下坡。新实验实施方案见本文末尾。

目前有 112 条最终版本的地面起步诊断，**68 条曾满足双后轮局部越阶条件，完整路线合格成功样本仍为 0**。这些局部越阶记录是当前优先参考的动作，用户观察其效果相近；不能解释成已经完成爬楼或已经通过真实硬件验证。

## 实验二：URDF 约束内的阶梯坡度上限（Sol 实施方案）

状态：2026-11-12 已完成首轮模型一致性核验与 11 条控制诊断。实现位于 AGX worktree `/home/agilex/wzy/rover-chaixm`，分支 `cxm`；执行解释器沿用 `/home/agilex/wzy/rover/.venv/bin/python`。首轮结果已接入 `/experiments/urdf-slope`，尚未推送 GitHub。

### 1. 用户已锁定的目标与约束

- 研究对象仍为等高直角楼梯，不改成光滑斜坡。单级高度 0.20 m，上行 15 级，总抬升始终 3.0 m；同一楼梯内踏步尺寸一致。
- 只改变楼梯整体倾角 θ，单级深度按 `d = 0.20 / tan(θ)` 生成。台阶竖直面保持竖直、踏面保持水平；不能整体旋转楼梯来改变坡度。
- 成功终点改为六轮上到顶部平台并正常停稳，不再要求下坡。旧完整路线审核不能用来裁判本实验。
- 机器人必须满足原 URDF 的全部明确字段与运行限值；六轮自身滑动摩擦参数按用户明确要求设为 0.6，台阶滑动摩擦分别 4/6/8，保留 MuJoCo 默认混合规则。
- 用户已明确：0.6 是轮胎参数，不是强制接触摩擦上限。当前无显式 contact pair、双方 priority=0 时，轮胎—台阶有效滑动摩擦会取较大值，仍为 4/6/8；不得写成“有效接触摩擦为 0.6”，也不得偷偷改 priority/pair 覆盖这个规则。
- 过程违规继续记录和录制，但任何 URDF 明确限值违规都取消该条的“合规通过”资格。非有限数值或仿真无法继续时记录技术失败并停止该条。
- 不测试其他台阶高度，不覆盖实验一原始数据，不沿用旧高摩擦检查点作为新初态。

当前 MuJoCo 版本为3.17.0。只读编译核验已确认：现有模型12个活动关节全部启用 `jnt_actfrclimited=1`，关节层合力限幅分别为六轮±50、转向±40、摇臂±100 N·m；控制器也有相应软件限幅。因此**目前50 N·m限制已经在使用**，不能误写成“只有软件限幅”或“发动机力矩一直超限”。执行器自身 `actuator_forcelimited=0`，轮子 `ctrlrange` 仍是±120，但这不等于关节实际驱动力矩可达120。新模型让输入范围与额定限制显式一致，并保存编译后实际开关、范围和gear；保留关节层合力限幅，避免多执行器叠加绕过限制。

旧审核中速度上限额外加0.01 rad/s、角限位允许1°，都是项目旧容差，不属于URDF。本实验按XML原值报告原始超出量，不采用这两项作为“合规许可”。浮点/积分边界问题须单独诊断，不事后加百分比或持续时间豁免。

URDF没有规定地球/火星重力、接触求解器、时间步长、软接触参数和完整自碰撞过滤策略。因此结果须称为“给定URDF明确参数及已声明仿真假设下的通过角度”，不能声称已验证实车绝对物理极限。

### 3. 开跑前门槛：模型合规清单

新建独立目录 `runs/urdf_slope_<date>/`，先生成 `model_compliance.json`；每项含原始文件/元素、原值、单位、编译后值、映射方式、是否通过，以及额外仿真假设。未通过不得开始角度批量测试。

1. 核对原始URDF哈希，解析全部96个body和82个碰撞体对应关系，逐项比较质量、质心、惯量、关节轴/原点、碰撞几何类型、尺寸和局部变换。原文件若发生变化，先显示差异，不能继续套旧基线。
2. 自动读取12个活动关节的position/velocity/effort/damping/friction，禁止把常量散落复制到多个脚本。连续轮关节不虚构位置限位。校验URDF所有明确字段均被映射或明确解释，不把“XML中存在”当作引擎已生效。
3. 显式设置机器人滑动摩擦0.6；轮胎值注明来自用户本次确认。导出每个geom的friction、priority、condim、接触过滤以及运行时contact.friction，核对4/6/8三种台阶实际接触结果。
4. 当前旧模型把机器人内部自碰撞全部屏蔽。新实验必须审查并去掉这种未经说明的全局禁碰；允许按引擎对同刚体、相邻运动学连接的默认过滤处理，但任何额外排除都要列出接触对和理由。发现原始简化碰撞体相互冲突时先报告，不能靠删碰撞体、缩尺寸或禁碰来制造通过。
5. 校验关节层总力矩限制、执行器范围、gear和软件输出限幅的一致性；逐步保存ctrl、actuator_force、qfrc_actuator，验收使用关节侧实际总驱动力矩。
6. 速度限值不能靠直接夹写qvel或qpos实现。控制器用有界目标、变化率、反馈和有限力矩工作；如果仍被接触反驱至超速，记录真实失败。可改进控制器以遵守限值，但正式扫角前冻结版本，改版后另立对照，不混算。
7. 用新模型从地面重新落稳并生成可复核初态；保留同一接近距离、横向位置、航向和初始关节配置。先做静置及小动作校验，再验证扫角将使用的轮速和±20°摇臂动作。所有检查本身也记录实际限值违规。

重力暂沿用[0,0,−9.81]m/s²；地面和平台滑动摩擦暂沿用4.0；平台长2m、楼梯宽5m；轮胎/结构的非滑动摩擦分量及solref等未在URDF声明的设置需明确列入冻结假设，不能称为甲方参数。平台须在开跑前核对能容纳六轮及停车余量，若不足先报告。物理基线先用1ms，控制周期1ms；边界另做0.5/0.2ms对照，控制周期保持1ms。

### 4. 角度与控制的试验顺序

正式比较时，只变θ和预先约定的台阶摩擦档位；同一控制编号的速度、触发、摆动及制动逻辑必须完全相同。

| 粗筛角度 | 单级深度m | 15级水平展开长m | 总抬升m |
|---:|---:|---:|---:|
| 15° | 0.746410 | 11.196152 | 3.0 |
| 25° | 0.428901 | 6.433521 | 3.0 |
| 35° | 0.285630 | 4.284444 | 3.0 |
| 45° | 0.200000 | 3.000000 | 3.0 |

第一批最多24条：4个粗筛角度 × 3个摩擦档 × SN/SP两种顺序。先从15°开始；六轮基础目标3 rad/s，前轮首次产生正法向台阶接触后触发，左右摇臂同向±20°、8秒/周期、3周期后回中立。SN先负后正，SP先正后负。采用经过前述门槛的同一控制器。3 rad/s只是首轮基线，不是URDF速度上限，也不预设它是唯一可合规速度。

若15°两方向都没有合格通过，先补5°、10°并分析是单级20cm阻挡、约束违规、控制不当还是超时，不盲目继续扩到更陡角度。若出现通过与未通过的区间，先补齐5°档位，再对边界附近逐1°细化。不要假设通过性严格单调，不能仅凭二分或一次失败跳过所有更陡档位。扫描范围先限5°～45°，若45°合规通过，结论先写“至少45°”，不自动扩到更陡角度。

为了避免把低速基线的上限误当成车的上限，在关键失败角度追加有界控制候选：基础轮速3/6/9/12/15 rad/s，首次接触/确认卡住两种触发，SN/SP两种顺序，共20个控制编号。卡住沿用“前轮已接触，连续2秒向前净位移不足2cm”的定义。已有完全一致组合直接引用；先在最近通过角和相邻未通过角比较，保留所有候选结果，不把旧实验中同名速度的结果当作新模型结果。每个控制编号仍跨角度冻结，不为某条单独偷改摩擦、力度、摇臂或审核。

若尚无任何通过角，则先在5°和10°按每个摩擦档比较这20个控制候选，不依赖“最近通过角”存在；仍无通过时只能报告“当前模型与控制集合未找到合格样本”，不能给出最大可爬角度或物理不可能结论。

若需要修改控制器来避免违规，生成新的controller版本与哈希，重新复核同一已通过/未通过角度，再继续搜索；不能把旧版失败与新版成功拼成同一个性能边界。

### 5. 观察窗口与成功判定

浅角度路径更长，不能一律观察120秒。每个角度在开跑前计算 `T_base=max(240, ceil(6*(接近段长度+15*d+平台长度)/(3*最小轮半径)))` 秒，所有同角度候选共享该预算，避免高速候选因预算更短而吃亏。若到预算末尾最近30秒净前移≥0.05m、仍在楼梯上且尚未到平台，每次延长60秒，最多600秒；超过预算仍未完成记“观察窗内未完成”。这只是时间预算，不是物理极限判断。发生违规不因此提前截断录像；明确非有限数值或引擎无法继续的技术失败除外。

分别保存三个独立布尔值：

- `ascent_completed`：六轮均越过最后一级前棱并进入平台，每个轮子有>5N平台法向支撑，连续至少1秒；顶部平台制动后车身正常姿态停稳。暂用滚转/俯仰≤3°、航向偏差≤5°、车身平移速度≤0.03m/s、角速度≤0.08rad/s、轮速≤0.2rad/s、摇臂/转向角速度≤0.1rad/s，连续至少1秒。完成后保留3秒停稳画面，不进入下坡。
- `urdf_compliant`：从起步至上述终点，每个物理步实际关节位置、速度和关节总驱动力矩均满足XML范围；模型明确参数映射也全部通过。旧±1°/+0.01容差不作为成功许可。
- `numerical_quality_ok`：无非有限数值、翻覆、越出赛道或持续结构支撑等异常；保存最大穿透、接触对和持续时间。20mm只沿用为项目数值预警上限，超过时不发布成功，低于它也不等于真实轮胎压缩合理。候选还需步长对照和视频复核。

本实验通过必须三者同时成立。5N、1秒、姿态/停车阈值和20mm均为本方案的工程验收判据，**不是URDF自带或甲方实测值**；若甲方另给标准，另立版本。实际违规后虽最终上平台，仍显示“到平台但不合规”；未登顶按违规、阻挡/打滑、超时和数值失败分别标注。下坡相关旧route_missing不能进入本实验失败原因。

### 6. 边界复核与交付

对每个摩擦档的最高合规通过角及相邻未通过角，用0.5ms和0.2ms物理步长复核，控制/触发周期保持1ms。比较是否仍通过、限值峰值、穿透、触发时刻与平台支撑；步长敏感时标为数值不稳健，不立即进入成功数据集。确定性同初态重跑是复现检查，不是独立成功率。后续如要统计稳健成功率，另设初态扰动范围和样本数。
